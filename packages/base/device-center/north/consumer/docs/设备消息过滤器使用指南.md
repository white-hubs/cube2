# 设备消息过滤器使用指南

## 概述

设备消息过滤器框架提供了一套灵活、易用的API，用于订阅和过滤设备消息（属性上报、事件触发、状态变更等）。框架采用装饰器模式和Builder模式，支持精细化的设备级和参数级过滤。

## 核心特性

- **设备级过滤**：指定关注的设备ID，只接收这些设备的消息
- **参数级过滤**：指定关注的属性code、事件code等，只接收相关消息
- **自动裁剪**：自动过滤掉不关心的数据字段，减少处理开销
- **状态变更检测**：智能检测设备在线/离线状态变化，避免重复通知
- **流式API**：采用Builder模式，链式调用，代码简洁优雅

## API详解

### 1. 设备属性消息过滤器

**类名**：`FilterableDevicePropMsgHandler`

**功能**：过滤设备属性上报消息，支持按设备ID和属性code过滤。

#### 使用示例

```java
import com.guhecloud.cube.iot.north.bridge.consumer.filter.FilterableDevicePropMsgHandler;
import com.guhecloud.cube.iot.north.bridge.consumer.vo.LivePropertyUpdateMsg;

// 示例1: 监听特定设备的特定属性
FilterableDevicePropMsgHandler propHandler =
    FilterableDevicePropMsgHandler.builder()
        .deviceId("device001")                    // 关注单个设备
        .propCodes("temperature", "humidity")     // 关注温度和湿度属性
        .build(msg -> {
            // 只会收到device001的temperature和humidity属性变化
            System.out.println("设备: " + msg.getDeviceId());
            msg.getUpdates().forEach(kv -> {
                System.out.println("属性: " + kv.getKey() + ", 值: " + kv.getValue());
            });
        });

// 示例2: 监听多个设备的所有属性
FilterableDevicePropMsgHandler multiDeviceHandler =
    FilterableDevicePropMsgHandler.builder()
        .deviceIds("device001", "device002", "device003")  // 关注多个设备
        .build(msg -> {
            // 收到这3个设备的所有属性变化
            handlePropertyUpdate(msg);
        });

// 示例3: 监听所有设备的特定属性
FilterableDevicePropMsgHandler allDeviceHandler =
    FilterableDevicePropMsgHandler.builder()
        .propCodes("battery", "signal")           // 只关注电池和信号强度
        .build(msg -> {
            // 收到所有设备的battery和signal属性变化
            logBatteryLevel(msg);
        });

// 示例4: 使用集合方式批量添加过滤条件
List<String> deviceList = Arrays.asList("device001", "device002", "device003");
Set<String> propSet = new HashSet<>(Arrays.asList("temperature", "humidity", "pressure"));

FilterableDevicePropMsgHandler batchHandler =
    FilterableDevicePropMsgHandler.builder()
        .deviceIds(deviceList)                    // 批量添加设备
        .propCodes(propSet)                       // 批量添加属性
        .build(msg -> {
            processWeatherData(msg);
        });
```

#### 特性说明

- **自动裁剪**：配置了`propCodes`后，消息的`updates`字段会自动过滤，只保留关心的属性
- **空过滤条件**：如果不设置任何过滤条件，则接收所有设备的所有属性消息

### 2. 设备事件消息过滤器

**类名**：`FilterableDeviceEventMsgHandler`

**功能**：过滤设备事件触发消息，支持按设备ID和事件code过滤。

#### 使用示例

```java
import com.guhecloud.cube.iot.north.bridge.consumer.filter.FilterableDeviceEventMsgHandler;
import com.guhecloud.cube.iot.north.bridge.consumer.vo.DeviceEventTriggerMsg;

// 示例1: 监听特定设备的特定事件
FilterableDeviceEventMsgHandler eventHandler =
    FilterableDeviceEventMsgHandler.builder()
        .deviceId("device001")                   // 关注单个设备
        .eventCodes("alarm", "fault")            // 关注告警和故障事件
        .build(msg -> {
            System.out.println("设备 " + msg.getDeviceId() +
                             " 触发事件: " + msg.getEventCode());
            System.out.println("事件参数: " + msg.getEventParam());
        });

// 示例2: 监听所有设备的紧急告警
FilterableDeviceEventMsgHandler emergencyHandler =
    FilterableDeviceEventMsgHandler.builder()
        .eventCodes("emergency_alarm", "critical_fault")  // 只关注紧急事件
        .build(msg -> {
            // 所有设备的紧急告警都会触发
            sendAlertNotification(msg);
        });

// 示例3: 监听特定设备的所有事件
FilterableDeviceEventMsgHandler deviceEventHandler =
    FilterableDeviceEventMsgHandler.builder()
        .deviceIds("device001", "device002")     // 关注多个设备
        .build(msg -> {
            // 这两个设备的所有事件
            logDeviceEvent(msg);
        });
```

### 3. 设备状态变更监听器

**类名**：`FilterableDeviceStatusChangeHandler`
**接口**：`DeviceOnlineStatusListener`

**功能**：监听设备在线/离线状态变化，自动去重，只在状态真正变化时触发回调。

#### 使用示例

```java
import com.guhecloud.cube.iot.north.bridge.consumer.filter.FilterableDeviceStatusChangeHandler;
import com.guhecloud.cube.iot.north.bridge.consumer.handler.DeviceOnlineStatusListener;

// 示例1: 监听特定设备的在线状态
FilterableDeviceStatusChangeHandler statusHandler =
    FilterableDeviceStatusChangeHandler.builder()
        .deviceIds("device001", "device002", "device003")
        .build((deviceId, isOnline) -> {
            if (isOnline) {
                System.out.println("设备 " + deviceId + " 上线了");
                notifyDeviceOnline(deviceId);
            } else {
                System.out.println("设备 " + deviceId + " 离线了");
                notifyDeviceOffline(deviceId);
            }
        });

// 示例2: 监听所有设备的在线状态（不指定设备ID）
FilterableDeviceStatusChangeHandler globalStatusHandler =
    FilterableDeviceStatusChangeHandler.builder()
        .build((deviceId, isOnline) -> {
            // 所有设备的状态变化都会触发
            updateDeviceStatusInDatabase(deviceId, isOnline);
            updateUIDisplay(deviceId, isOnline);
        });

// 示例3: 使用Lambda表达式实现监听器
DeviceOnlineStatusListener listener = (deviceId, isOnline) -> {
    String status = isOnline ? "在线" : "离线";
    logger.info("设备状态变更: {} -> {}", deviceId, status);

    // 发送WebSocket推送到前端
    webSocketService.pushDeviceStatus(deviceId, status);
};

FilterableDeviceStatusChangeHandler handler =
    FilterableDeviceStatusChangeHandler.builder()
        .deviceId("device001")
        .build(listener);

// 示例4: 手动清除缓存
// 当设备被删除或不再需要监听时，可以清除缓存
handler.clearDeviceCache("device001");  // 清除单个设备缓存
handler.clearAllCache();                // 清除所有缓存
```

#### 特性说明

- **状态去重**：内部维护状态缓存，只有状态真正变化时才触发回调
- **线程安全**：使用`ConcurrentHashMap`保证并发安全
- **缓存管理**：提供`clearDeviceCache`和`clearAllCache`方法管理缓存

### 2. 运行时动态管理过滤条件（推荐）

从 v1.1.0 开始，支持运行时动态添加/移除设备ID和参数code，无需重新创建Handler。

#### 动态管理API说明

| 方法 | 说明 | 线程安全 |
|------|------|---------|
| `addDeviceId(String)` | 添加单个设备ID | ✅ |
| `addDeviceIds(Collection)` | 批量添加设备ID | ✅ |
| `removeDeviceId(String)` | 移除单个设备ID | ✅ |
| `removeDeviceIds(Collection)` | 批量移除设备ID | ✅ |
| `clearDeviceIds()` | 清空所有设备ID | ✅ |
| `addParamCode(String)` | 添加单个参数code | ✅ |
| `addParamCodes(Collection)` | 批量添加参数code | ✅ |
| `removeParamCode(String)` | 移除单个参数code | ✅ |
| `removeParamCodes(Collection)` | 批量移除参数code | ✅ |
| `clearParamCodes()` | 清空所有参数code | ✅ |
| `getFilterCriteria()` | 获取FilterCriteria对象 | ✅ |

**场景2：用户订阅管理**

```java
@Service
public class UserSubscriptionService {

    private final Map<String, FilterableDevicePropMsgHandler> userHandlers = new ConcurrentHashMap<>();

    /**
     * 用户订阅设备
     */
    public void subscribeDevice(String userId, String deviceId) {
        FilterableDevicePropMsgHandler handler = userHandlers.computeIfAbsent(userId, k ->
            FilterableDevicePropMsgHandler.builder()
                .build(msg -> notifyUser(userId, msg))
        );

        handler.addDeviceId(deviceId);
        log.info("用户 {} 订阅了设备 {}", userId, deviceId);
    }

    /**
     * 用户取消订阅设备
     */
    public void unsubscribeDevice(String userId, String deviceId) {
        FilterableDevicePropMsgHandler handler = userHandlers.get(userId);
        if (handler != null) {
            handler.removeDeviceId(deviceId);
            log.info("用户 {} 取消订阅设备 {}", userId, deviceId);
        }
    }

    /**
     * 用户订阅特定属性
     */
    public void subscribeProperty(String userId, String propCode) {
        FilterableDevicePropMsgHandler handler = userHandlers.get(userId);
        if (handler != null) {
            handler.addParamCode(propCode);
            log.info("用户 {} 订阅了属性 {}", userId, propCode);
        }
    }

    private void notifyUser(String userId, LivePropertyUpdateMsg msg) {
        // 推送消息给用户
        webSocketService.sendToUser(userId, msg);
    }
}
```

**场景3：动态告警规则**

```java
@Service
public class AlarmRuleService {

    private FilterableDeviceEventMsgHandler eventHandler;

    @PostConstruct
    public void init() {
        eventHandler = FilterableDeviceEventMsgHandler.builder()
            .build(this::handleAlarmEvent);
    }

    /**
     * 添加告警规则
     */
    public void addAlarmRule(String deviceId, String eventCode) {
        eventHandler.addDeviceId(deviceId);
        eventHandler.addParamCode(eventCode);
        log.info("添加告警规则: 设备={}, 事件={}", deviceId, eventCode);
    }

    /**
     * 移除告警规则
     */
    public void removeAlarmRule(String deviceId, String eventCode) {
        eventHandler.removeDeviceId(deviceId);
        eventHandler.removeParamCode(eventCode);
        log.info("移除告警规则: 设备={}, 事件={}", deviceId, eventCode);
    }

    /**
     * 批量更新告警规则
     */
    public void updateAlarmRules(List<AlarmRule> rules) {
        // 清空现有规则
        eventHandler.clearDeviceIds();
        eventHandler.clearParamCodes();

        // 添加新规则
        Set<String> deviceIds = rules.stream()
            .map(AlarmRule::getDeviceId)
            .collect(Collectors.toSet());
        Set<String> eventCodes = rules.stream()
            .map(AlarmRule::getEventCode)
            .collect(Collectors.toSet());

        eventHandler.addDeviceIds(deviceIds);
        eventHandler.addParamCodes(eventCodes);

        log.info("批量更新告警规则: {} 个设备, {} 个事件", deviceIds.size(), eventCodes.size());
    }

    private void handleAlarmEvent(DeviceEventTriggerMsg msg) {
        // 处理告警事件
        log.warn("收到告警: 设备={}, 事件={}", msg.getDeviceId(), msg.getEventCode());
        sendAlarmNotification(msg);
    }
}
```

#### 常见问题

**Q1: 动态添加设备后，多久生效？**

**A**: 立即生效。下一条消息到达时就会使用新的过滤条件。

**Q2: 动态修改过滤条件会影响正在处理的消息吗？**

**A**: 不会。正在处理的消息使用的是进入过滤逻辑时的过滤条件快照。

**Q3: 可以在消息处理回调中动态修改过滤条件吗？**

**A**: 可以，但要注意避免死锁。建议在回调中使用异步方式修改：

```java
FilterableDevicePropMsgHandler handler = FilterableDevicePropMsgHandler.builder()
    .build(msg -> {
        // ✅ 推荐：异步修改
        CompletableFuture.runAsync(() -> {
            handler.addDeviceId("newDevice");
        });
    });
```

### 3. 自定义过滤逻辑

如果内置的过滤器不满足需求，可以继承`AbstractFilterableHandler`自定义过滤器：

```java
public class CustomDeviceFilterHandler
    extends AbstractFilterableHandler<CustomMsg, CustomMsgHandler>
    implements CustomMsgHandler {

    public CustomDeviceFilterHandler(FilterCriteria criteria, CustomMsgHandler delegate) {
        super(criteria, delegate);
    }

    @Override
    protected String extractDeviceId(CustomMsg msg) {
        // 自定义设备ID提取逻辑
        return msg.getCustomDeviceId();
    }

    @Override
    protected Set<String> extractParams(CustomMsg msg) {
        // 自定义参数提取逻辑
        return msg.getCustomParams();
    }

    @Override
    public void handle(CustomMsg msg) {
        if (!shouldProcess(msg)) {
            return;
        }
        delegate.handle(msg);
    }
}
```

```java
        .propCodes("temperature")  // 只关注温度

// ❌ 不推荐: 接收所有消息后再手动过滤
FilterableDevicePropMsgHandler handler =
    FilterableDevicePropMsgHandler.builder()
        .build(msg -> {
            if ("device001".equals(msg.getDeviceId())) {
                // 手动过滤，浪费资源
                processTemperature(msg);
            }
        });
```

### 2. 避免重复订阅

```java
// ❌ 错误: 重复订阅同一设备
FilterableDevicePropMsgHandler handler1 =
    FilterableDevicePropMsgHandler.builder()
        .deviceId("device001")
        .build(msg -> handler1Logic(msg));

FilterableDevicePropMsgHandler handler2 =
    FilterableDevicePropMsgHandler.builder()
        .deviceId("device001")  // 重复订阅
        .build(msg -> handler2Logic(msg));

// ✅ 正确: 合并处理逻辑
FilterableDevicePropMsgHandler handler =
    FilterableDevicePropMsgHandler.builder()
        .deviceId("device001")
        .build(msg -> {
            handler1Logic(msg);
            handler2Logic(msg);
        });
```

### 3. 注意内存泄漏

```java
@Service
public class DeviceService {

    private Map<String, FilterableDevicePropMsgHandler> handlers = new ConcurrentHashMap<>();

    public void subscribeDevice(String deviceId) {
        FilterableDevicePropMsgHandler handler =
            FilterableDevicePropMsgHandler.builder()
                .deviceId(deviceId)
                .build(msg -> processMsg(msg));

        handlers.put(deviceId, handler);
        container.registerPropHandler(handler);
    }

    // ✅ 重要: 设备删除时要清理资源
    public void unsubscribeDevice(String deviceId) {
        FilterableDevicePropMsgHandler handler = handlers.remove(deviceId);
        if (handler != null) {
            container.unregisterPropHandler(handler);
        }
    }
}
```

## 常见问题

### Q1: 为什么我的Handler没有收到消息？

**可能原因**：
1. 过滤条件设置过严，消息被过滤掉了
2. Handler未正确注册到Container
3. 设备ID或参数code拼写错误

**排查方法**：
```java
// 临时移除所有过滤条件，验证是否收到消息
FilterableDevicePropMsgHandler handler =
    FilterableDevicePropMsgHandler.builder()
        .build(msg -> {
            System.out.println("收到消息: " + msg);
        });
```

### Q2: 设备状态变化了，但没有触发回调？

**可能原因**：状态未真正变化（从在线到在线，或从离线到离线）

**解决方案**：`FilterableDeviceStatusChangeHandler`只在状态真正变化时触发，这是设计行为。如需每次都触发，请使用基础的`DeviceStatusHandler`。

### Q3: 如何知道当前有哪些设备在线？

```java
FilterableDeviceStatusChangeHandler handler =
    FilterableDeviceStatusChangeHandler.builder()
        .build((deviceId, isOnline) -> {
            if (isOnline) {
                onlineDevices.add(deviceId);
            } else {
                onlineDevices.remove(deviceId);
            }
        });
```

## 性能优化建议

### 1. 精确过滤

尽量使用设备ID和参数code过滤，避免接收大量无关消息：

```java
// ✅ 推荐：精确过滤
FilterableDevicePropMsgHandler handler =
    FilterableDevicePropMsgHandler.builder()
        .deviceId("device001")
        .propCodes("temperature")
        .build(msg -> processMsg(msg));

// ❌ 不推荐：接收所有消息后手动过滤
FilterableDevicePropMsgHandler handler =
    FilterableDevicePropMsgHandler.builder()
        .build(msg -> {
            if ("device001".equals(msg.getDeviceId())) {
                processMsg(msg);
            }
        });
```

### 2. 批量操作优先

使用批量方法而非多次调用单个方法：

```java
// ✅ 推荐：批量添加
handler.addDeviceIds(Arrays.asList("device001", "device002", "device003"));

// ❌ 不推荐：多次单个添加
handler.addDeviceId("device001");
handler.addDeviceId("device002");
handler.addDeviceId("device003");
```

### 3. 异步处理

如果消息处理逻辑耗时较长，建议在Handler中异步处理：

```java
FilterableDevicePropMsgHandler handler =
    FilterableDevicePropMsgHandler.builder()
        .deviceId("device001")
        .build(msg -> {
            // 异步处理，避免阻塞消息接收
            CompletableFuture.runAsync(() -> {
                heavyProcessing(msg);
            });
        });
```

### 4. 线程安全性能说明

框架使用 `ReentrantReadWriteLock`（非公平模式）实现线程安全：

- **读操作**（过滤消息）：多线程并发读取，无阻塞，性能优秀
- **写操作**（动态修改）：独占锁，会阻塞读操作

**性能特点**：
- 适合读多写少场景（90%读 / 10%写）
- 读操作吞吐量高，延迟低
- 写操作会短暂阻塞读操作，但影响很小

**最佳实践**：
```java
// ✅ 推荐：批量修改，减少写锁次数
handler.addDeviceIds(newDevices);  // 一次写锁

// ❌ 不推荐：频繁单个修改
for (String device : newDevices) {
    handler.addDeviceId(device);  // 多次写锁
}
```

**多线程并发示例**：

所有动态管理方法都是线程安全的，可以在多线程环境下安全调用：

```java
// 多线程并发添加设备
ExecutorService executor = Executors.newFixedThreadPool(10);
FilterableDevicePropMsgHandler handler = FilterableDevicePropMsgHandler.builder()
    .build(msg -> processMsg(msg));

for (int i = 0; i < 100; i++) {
    final String deviceId = "device" + i;
    executor.submit(() -> {
        handler.addDeviceId(deviceId);
    });
}

// 所有操作都是线程安全的，不会出现数据不一致
```

### 5. 避免在回调中同步修改过滤条件

```java
// ❌ 不推荐：可能导致死锁
FilterableDevicePropMsgHandler handler =
    FilterableDevicePropMsgHandler.builder()
        .build(msg -> {
            handler.addDeviceId("newDevice");  // 危险：在读锁中获取写锁
        });

// ✅ 推荐：异步修改
FilterableDevicePropMsgHandler handler =
    FilterableDevicePropMsgHandler.builder()
        .build(msg -> {
            CompletableFuture.runAsync(() -> {
                handler.addDeviceId("newDevice");
            });
        });
```
