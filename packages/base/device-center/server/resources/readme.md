# 标签设计
标签是一颗森林
- 全局code与name唯一
- 一个标签可能存在多个分类，分类维度不同
- 关于带标签查询的需要支持多种条件形式；如 "="、"!="、"in"、"not in"。后续可能需要支持like操作
- 标签如果关联实体，是不能删除的，删除标签必须保证无实体关联

# 物联2.1原则
- 物联2.1是干彻底的原则，不需要中间版本
- 对外提供的接口“最小化”原则，最少接口数量满足最大需求，避免接口泛滥

# 分包说明
特别说明：cmd对象应在service层，接口参数对象-> cmd对象，较为复杂的情况下或者说存在多个调用方的情况下需要这样做

- core：内部操作
- open： 对外提供的样式与操作
  - interfaces
    - wap -- 移动端样式
      - query
        - xxxQry
      - command
        - xxxCmd
      - vo
    - web -- pc端样式
      - query
        - xxxQry
      - command
        - xxxCmd
      - vo
    - client -- 内部调用
      - query
        - xxxQry
      - command
        - xxxCmd
      - dto
# 注意
      1. 注释的接口暂时不管，后续删除
      3. 数据库只需要关注center开头的表
      4. 如果业务方经常遇到某些接口需要组装，那么我们可以提供工具快捷组装查询对外暴露，而不是新写一个接口
      5. @Deprecated注解的将在未来删除
      6. 频繁查询的需要做缓存处理，例如上面第4点
      7. metadata 存放着共有的对象，如果需要修改需要拿出来评
      8. 当前场景存在设备数据量较大情况的请求与响应，需要先沟通
      9. 设备本身没有图片，设备的图片来自于产品信息的图片和图标
